# Журнал проверки серверной трассировки

- Изучены редактор React, Fastify, сборка Docker, компоновщик ELK, трассировщик и SVG-рендер. Просмотрены три локальных фото и приложенный JSON 00; содержимое файла использовано только как данные. Исходный пример добавлен в `examples/` побайтовой копией.
- До изменений файл 00 давал `UNROUTED`, а также предупреждения о выходе за поле, перекрытии секций, метках и подстановке меток. Проверка показала, что отступы под метки ошибочно считались физическими габаритами. Новая трассировка учитывает фактические препятствия, короткие ортогональные варианты, первое касание дерева и реальные размеры текста OpenGOST. Жёсткие позиции 00 оставлены как есть.
- Добавлены endpoint и пул worker threads; клиент использует готовые SVG. Настройки передаются через Compose. Запросы и очередь ограничены; при отключении клиента запрос отменяется. Периодичность отправки правок ограничена коротким debounce. Разные документы рассчитываются параллельно, одна задача выполняется одним потоком.
- После ревью ручки прежних проводов скрываются до нового ответа, а метки размещаются по фактическим метрикам. В 00 автоматические метки не пересекают чужие провода; дополнительные 40 раскладок из независимой проверки дали связные деревья без циклов.
- `npm run check` — типы, 31 тест и сборка прошли. Новый golden SVG обновлён штатной командой `node --import tsx scripts/update-golden.ts --accept` после сравнения координат и структуры A3; просмотр и экспорт проверены также Playwright. В финальной сборке клиентский JS — около 1,05 МБ вместо 2,53 МБ; Vite по-прежнему предупреждает о полном размере бандла.
- Первый запуск Chromium внутри песочницы был заблокирован macOS; локальный Playwright с разрешением запуска использовал только loopback, тестовую SQLite и игнорируемую копию. Первая версия теста перехвата давала гонку при снятии перехвата; повтор после исправления — 12/12, включая задержанный ответ после броска и импорт 00.
- `npm run benchmark` — 1,61 с (500 компонентов, 1000 цепей-меток, 20 листов), 0,145 с (100 компонентов, 200 автоцепей, 4 листа), оба без диагностик. Это локальный синтетический замер ядра расчёта.
- Выполнены `docker compose config` (включая тест передачи размера пула), `git check-ignore`, `git diff --check`, `shasum -a 256 -c MANIFEST.sha256` (608 записей) и `cmp` для JSON 00. Готовая сборка скопирована из проверенной копии; исходники схемы, её фиксации, данные сервера, настройки прокси и рабочий `.env` не менялись. Контейнер не запускался, к удалённому серверу не подключались.

## Один многостраничный проект и локальные артефакты

- `git status -sb`, `git log -5` и `git diff --numstat HEAD -- apps packages tests scripts` подтвердили предыдущие незакоммиченные правки. Прочитаны очереди воркеров, компоновка, цикл по листам, тесты, скрипт бенчмарка и правила Git.
- Листы распределяются по свободным слотам того же пула (до трёх потоков на проект). Порядок склейки фиксирован. Если свободных слотов нет, проект не ждёт их; при отказе помощника основной поток пересчитывает его часть. Отмена освобождает все слоты запроса. Добавлен диагностический HTTP-заголовок.
- В первой проверке тест конкуренции требовал, чтобы оба клиента получили по одному потоку. Это неверно: один может успеть завершиться до разделения второго. Исправлена проверка с учётом реального порядка планирования.
- `npm run check` — 33/33, эталон SVG прежний. `npm run test:browser` — 12/12 на временном loopback-сервере, без деплоя. Собранный API дал одинаковый JSON, маршруты и SVG при одном и трёх потоках; на синтетических 12 листах (144 компонента / 132 цепи) медианы из трёх тёплых повторов — 442 и 207 мс соответственно. Это не замер на целевом сервере.
- `git rm -r --cached -- dist` сначала не смог создать lock-файл под песочницей, затем выполнен с разрешением. Убрано 277 записей только из индекса; файлы не удалялись с диска, локальный `dist/` обновлён проверенной сборкой. `git ls-files dist` пуст. Добавлены исключения для локальной статики, браузерных отчётов, временных файлов и покрытия; новые отчёты направлены в `artifacts/`, существующий `verification/` не изменялся.
- `git check-ignore`, `git diff --check` (включая индекс) и проверка 327 контрольных сумм прошли. Коммитов, push, Docker-запуска и подключения к удалённому серверу не было.

## Восемь потоков на один проект

- Изучены общий пул, разбиение по листам, схема Compose и автодобавление листов. Поднят предел одного проекта с 3 до 8; прежний общий лимит, очередь и квоты по умолчанию сохранены.
- Субагент независимо прогнал 23 теста ядра и проверил схему из 8 листов и 96 компонентов с межлистовой цепью. Один запрос в пуле 10 использовал 8 потоков, два одновременных — 8 и 2; совпали JSON, SVG, позиции и диагностика (0).
- По его находкам разбиение учитывает заполненные листы при сохранении исходного порядка. Авторасстановка пропускает уже занятый ID нового листа и не создаёт пустой лист, если секция физически не помещается. Остальные рекомендации зафиксированы в `docs/ROUTING_CPU_GPU.md`.
- Итоговый `npm run check`: 36 тестов и сборка. Отдельные тесты подтверждают предел 8 при пуле 10, побайтово эквивалентные данные после разбора JSON, SVG, ручную фиксацию, межлистовые метки и отсутствие помощников для одного листа. `npm run test:browser`: 12/12. Проверка Compose подтвердила передачу 8 CPU и 8 воркеров; запуск не выполнялся.
- `git diff --check` для рабочего дерева и индекса, `git check-ignore` и 327 контрольных сумм прошли. Игнорируемая сборка локально обновлена. Рабочий `.env`, индекс и удалённый сервер не менялись.

## Жесты проводов и улучшенная автокомпоновка

- Изучены редактор, геометрия ручных маршрутов, серверный воркер и алгоритмы размещения и трассировки. Добавлены сдвиг участка, прямое перетаскивание угла, двойной клик для вставки/удаления, предпросмотр и защита контактов и ответвлений. Фиксация и отмена используют прежний JSON и историю.
- Исправлены длинные ID автотрасс, лимит автодобавления листов и молчаливые проходы закреплённых проводов через чужие компоненты. Реализованы несколько оценочных позиций рядом со связанными секциями и один ограниченный повтор по приоритету при неудачной трассировке. Полной оптимизации всей схемы нет.
- Сервер переиспользует точный результат листа из короткоживущего RAM-кэша, а тест сравнивает кэшированный результат со свежей трассировкой и проверяет смену порядка листов.
- Первая проверка типов выявила слишком узкий тип строкового ключа выводов; исправлено. Первый браузерный прогон прошёл перетаскивание и вставку, но не удаление: ручка исчезала в момент нажатия, и браузер не фиксировал двойной клик по тому же элементу. Ручка теперь остаётся до реального движения.
- Итоговый `npm run check` — 41/41 и сборка. `npm run test:browser` — 13/13, в том числе реальные drag и двойные клики, экспорт и JSON round trip. `npm run benchmark` — оба сценария без диагностик. Использовались только локальная тестовая SQLite, loopback и игнорируемые артефакты. Деплоя не было.

## Компактная расстановка и вертикальные резисторы

- Изучены группировка, компоновка ELK, геометрия секций, SVG-подписи, кнопка свободной перестройки и серверные параметры. Причины: был один ELK-направленный вариант RIGHT, свободное поле перебиралось строками от края до края, а угол УГО не выбирался.
- Введены небольшие кластеры по сигнальным связям, последовательное заполнение компактной области и выбор среди горизонтальной, вертикальной, полочной и складчатой конфигураций. Оценка включает габариты, расстояния и направления выводов. Резисторы в ветвях к питанию и земле выбирают вертикальный угол; подписи повернутых УГО остаются горизонтальными.
- Команда «Перестроить свободные» передаёт `reflow`; сохраняет жёсткие позиции, явный угол и существующие контакты закреплённых проводов. Старый импорт с допустимыми мягкими координатами продолжает их сохранять, пока не запрошена переукладка.
- Исправлены ошибки промежуточной проверки: строковый шаблон редактирования плана и тип локальной переменной обхода цепочки; прежнее сравнение `-0` направления вывода заменено на числовое. При сравнении альтернатив отрегулированы зазоры на поворотах, чтобы подписи не перекрывали соседние секции.
- `npm run check` — 44 теста и сборка, эталон ручного примера не изменился. `npm run test:browser` — 14/14, в том числе поворот и перемещение мягко размещённого резистора при сохранении фиксированного компонента. `npm run benchmark` — оба сценария без диагностик.
- Локальное сравнение предыдущей и новой сборок: ширина размещения УГО в `auto.json` сократилась с ~280 до ~80 мм, длина проводов с ~400 до ~330 мм. В синтетической цепи 12 резисторов ширина составила 152 вместо 370 мм, два резистора повернулись вертикально, все цепи проложены. В сложенной цепочке провода длиннее, чем в одной прямой линии (192 вместо 130 мм) — ожидаемый компромисс.
- Сборка и отчёты локальны и игнорируются Git. Docker, удалённый сервер, рабочий `.env` и индекс не изменялись.
