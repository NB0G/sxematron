# Схематрон

Автономное веб-приложение для библиотеки УГО, генерации и ручного редактирования принципиальных схем, экспорта листов **А3 420 × 297 мм**. Интерфейс на русском, Material Design 3, светлая/тёмная тема. В комплекте только типовые и вымышленные тестовые компоненты.

## Быстрый запуск Docker

Требования: Linux x86-64, Docker Engine с Compose v2, ориентир 2 CPU / 2 ГиБ RAM. Первый `build` скачивает базовый образ и зависимости. После сборки приложение работает полностью автономно: без CDN, внешних API, аккаунтов и запросов к нейросетям.

```bash
docker compose up -d --build
```

По умолчанию сайт доступен по адресу **http://localhost:3000**. Docker публикует порт только на `127.0.0.1`. Для удалённого доступа используйте SSH-туннель или reverse proxy с авторизацией: в самом приложении её нет.

Если хотите изменить настройки, один раз скопируйте [`.env.example`](.env.example) в локальный `.env` рядом с `compose.yaml`. Если `.env` уже есть, просто отредактируйте его. При запуске из корня репозитория Compose прочитает `.env` автоматически, без `--env-file`.

```bash
cp -n .env.example .env   # не перезаписывает существующий .env
docker compose config    # проверить настройки без запуска
```

В `.env` доступны четыре параметра: `BIND_ADDRESS` — адрес хоста, `PORT` — порт хоста, `CPU_LIMIT` и `MEMORY_LIMIT` — лимиты контейнера. Если reverse proxy работает на том же хосте и обращается к `127.0.0.1:3000`, менять адрес и порт не нужно. Переменные из оболочки имеют приоритет над `.env`; для отсутствующих или пустых значений действуют дефолты из `compose.yaml`.

Если вы уже меняли настройки в прежнем `compose.env`, перенесите свои значения в `.env`.

Контейнер называется `sxematron`, локальный образ — `sxematron:local`. Файл `.dockerignore` исключает, например, `AGENTS.md`, локальный `.env` и `node_modules` из контекста сборки. Он не влияет на то, какой файл с настройками читает Compose.

```bash
docker compose logs -f
docker compose ps
docker compose down
```

Библиотека хранится в именованном томе `library-data`, файл `/data/library.sqlite`. `down` и пересборка том не удаляют. **`down -v` удалит библиотеку.** Контейнер работает от непривилегированного пользователя, с read-only корнем; запись разрешена в `/data` и временный `/tmp`.

Если машина полностью отключена от Интернета, образ нужно заранее собрать на подключённой машине и перенести через `docker save` / `docker load`:

```bash
docker compose build
docker save sxematron:local -o sxematron-image.tar
# На автономной машине после передачи sxematron-image.tar и файлов проекта:
docker load -i sxematron-image.tar
docker compose up -d --no-build
```

## Начать работу

1. Открыть «Схемы» → «Открыть пример» либо загрузить `examples/demo.json`.
2. Выбрать лист. В демонстрации секции A/B и питание принадлежат одному физическому компоненту, но находятся на двух листах.
3. Перетаскивать секции; координаты фиксируются в миллиметрах. Перемещение не меняет электрические цепи. Для панорамы — пробел + перетаскивание или средняя кнопка; для масштаба — Ctrl + колесо.
4. Нажать «Компонент» для добавления из библиотеки; вариант УГО выбирается явно, все его секции обязательны. Вывод на рисунке открывает редактор цепи. Роль питания относится к **цепи**, а не к электрическому типу вывода.
5. Выбрать провод и изменить точки перегиба; ручной маршрут фиксируется. Если после перемещения секции он перестал доходить до контакта, журнал укажет разрыв; исправить маршрут или снять его фиксацию. Выделение и сетка отсутствуют в экспорте.
6. «Перестроить свободные» сохраняет фиксацию. Полная перестройка требует подтверждения. Позиционные обозначения сохраняются; перенумерация — отдельная команда.
7. Скачать **JSON**, чтобы сохранить работу. Проект существует только в памяти вкладки: сервер, localStorage и IndexedDB его не сохраняют. В localStorage хранится только тема интерфейса. При закрытии вкладки браузер предупреждает о несохранённых изменениях.
8. Скачать SVG или ZIP всех листов. Для печати оставить «Контуры»: текст переводится в векторные контуры OpenGOST Type B. Если снять флажок, SVG содержит редактируемый текст со встроенным шрифтом. **Печатать А3, альбомно, масштаб 100%, без подгонки.** Подробнее — `docs/PRINT_AND_STANDARDS.md`.

«Конструктор» позволяет рисовать линии, ломаные, прямоугольники, окружности, дуги, многоугольники, текст и группы; размещать номера выводов; создавать секции и варианты; импортировать Component JSON. Свойства, поворот, отражение, выравнивание, undo/redo и предпросмотр доступны на экране. Для сохранения каждый физический номер должен быть показан ровно один раз в каждом варианте. Назначений, имён и электрических типов выводов в модели нет.

«Библиотека» поддерживает поиск, копирование, редактирование, удаление, импорт и экспорт. Коды компонентов неизменны и не переиспользуются после удаления. Импорт всей библиотеки транзакционный; отличающиеся записи заменяются явно. Удалённые коды входят в экспорт резервирований. История определений не хранится. Изменение определения видно по контрольному отпечатку в схеме; отсутствующие коды/секции/выводы блокируют построение.

В «Документах» доступны инструкции для внешней нейросети и **динамический каталог из SQLite**. Нейросеть используется вне сайта: ей передаются Markdown и каталог, а полученный JSON загружается обратно. Текстового JSON-редактора в приложении нет.

## Работа с нескольких устройств

Несколько человек могут одновременно открыть один сайт и независимо редактировать свои схемы. Каждая схема живёт в памяти своей вкладки, а не на сервере. Чтобы сохранить её или перенести на другой компьютер, скачайте JSON и откройте его там. Аккаунтов, облачного хранения схем и совместного редактирования одного файла нет.

Библиотека УГО, напротив, общая для всех устройств. Любой допущенный к сайту пользователь может менять или удалять компоненты, от которых зависят чужие схемы. Если сайт доступен не только с вашего компьютера, ограничьте доступ на reverse proxy или через VPN. С приватными библиотеками или отдельными правами приложение не работает.

## Примеры

- `examples/library.json` — начальная библиотека девяти типовых и синтетических определений.
- `examples/demo.json` — ручные позиции, несколько секций одной микросхемы, два листа.
- `examples/auto.json` — тот же пример без жёстких позиций, групповая компоновка.
- `examples/repeated.json` — три материализуемых RC-каскада с разными локальными цепями и явно общим портом.
- `examples/invalid_pin.json` — намеренная ошибка физического номера вывода.
- `examples/component_multisection.json` — Component JSON с двумя вариантами УГО.

Начальная библиотека загружается только один раз. Если затем удалить её целиком, перезапуск не восстановит удалённые компоненты.

## Разработка и тесты без Docker

Node.js **24+**, npm. Git не требуется.

```bash
npm ci
npm run check
npm run dev
```

Разработка: Vite http://localhost:5173 и Fastify http://localhost:3000. Продакшен напрямую:

```bash
npm run build
DATA_DIR=./data npm start
```

На Windows задать `DATA_DIR` средствами PowerShell либо оставить значение по умолчанию `./data`.

```bash
npm test                         # доменная модель, API, экспорт, безопасность, маршруты
npm run typecheck
npm run benchmark                # 500 компонентов / 1000 цепей / 20 листов
npx playwright install chromium # один раз для дополнительных браузерных тестов
npm run test:browser              # после npm run build; собственная временная БД
bash scripts/docker-smoke.sh      # проверка контейнера на машине с Docker
```

Dockerfile выполняет `npm run check` перед сборкой конечного образа. JSON-валидаторы предварительно компилируются: приложение не требует `unsafe-eval` и соблюдает CSP. Архив содержит lockfile, собранную статику и сервер; для запуска собранного сервера нужны `npm ci --omit=dev` и Node 24. Готового Docker-образа в архиве нет.

## Резервные копии библиотеки

Экспорт JSON доступен в интерфейсе. Консистентная SQLite-копия, включая WAL-коммиты:

```bash
curl --fail http://127.0.0.1:3000/api/library/backup.sqlite -o library-backup.sqlite
```

JSON импортируется через интерфейс. Для восстановления SQLite остановить контейнер, восстановить копию файла в `/data/library.sqlite` и удалить старые `library.sqlite-wal`/`library.sqlite-shm` только при остановленном приложении. Не копировать рабочую SQLite-базу простым `cp` во время работы; endpoint использует `VACUUM INTO`.

## Архитектура

- `apps/web` — React/MUI, редактор схем, конструктор, библиотека и документация.
- `apps/server` — Fastify, SQLite, миграции, CRUD и каталог; никаких серверных проектов.
- `packages/core/src/types.ts`, `schemas.ts`, `validation.ts` — контракты и проверки.
- `layout.ts` — материализация повторов, обозначения, ELK, группы, страницы, жёсткие/мягкие координаты.
- `routing.ts` — ортогональный A*, провода, именованные цепи, межлистовые продолжения, контроль разрывов.
- `geometry.ts`, `render.ts`, `font.ts` — единый preview/export renderer в мм, лист, штамп и лицензированный шрифт.
- `scripts/compile-validators.ts` — генерация статических валидаторов Ajv без исполнения кода из JSON.
- `tests`, `verification` — проверки, измерения и примеры результатов.

Нормативные параметры редактируются в исходниках, пользовательского экрана настройки ГОСТ нет. Электрическая связность — множество `(instance_id, number)`, независимое от SVG. Одинаковые имена разных net IDs сами по себе не объединяют цепи. Внешние порты повторов соединяются только явными ссылками. Геометрические пересечения разных цепей не образуют электрический узел.

## Границы проверенного результата

Это работающий редактор и генератор, **не сертификат соответствия ЕСКД**. А3, физические размеры, Type B, векторный экспорт и инварианты модели проверены. Точная нормативная геометрия основной надписи, обозначения разнесённых секций и адресация межлистовых цепей должны пройти окончательную сверку по вашим эталонам; модули для таких правок выделены. Временная адресация продолжений — имя цепи и номера листов.

Раскладка эвристическая: невозможно обещать удобный чертёж для любого графа. При невозможности проложить ветвь в режиме `auto` применяются именованные метки с предупреждением. Для принудительного `wire` непроложенная ветвь — ошибка и экспорт блокируется. Жёсткие позиции не исправляются молча; коллизии выводятся в журнал. Плотные схемы требуют ручных правок. Проверка электрической правильности схемы и обвязки неиспользованных секций не выполняется.

Полное сенсорное управление не реализовано. Аккаунты, совместное редактирование одной схемы, PDF/DXF/KiCad-экспорт и реальные дипломные компоненты в поставку не включены.

Проверки текущей поставки и существенные ограничения среды — `verification/REPORT.md`.
