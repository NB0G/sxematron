# Результат: серверная компоновка и трассировка

Расстановка, трассировка и подготовка интерактивного SVG работают в пуле серверных CPU-потоков. Параллельность — между запросами, а не внутри одного чертежа. При перетаскивании картинка следует за курсором, провода и метки на текущем листе скрыты до готового ответа. Редактор не сохраняет проекты на диске сервера.

Автотрассировка предпочитает компактные пути и меньше поворотов, не строит петлю при подключении к своему дереву. Пример `00_smoke_import.json` открывается с 12 секциями, без ошибок и предупреждений, с исходными фиксированными позициями. Он доступен для скачивания. Папка фотографий исключена из Git и Docker.

**Файлы:** серверный endpoint и два модуля воркеров в `apps/server/src/`; редактор, экран примеров и CSS в `apps/web/src/`; компоновка, трассировка, шрифт и SVG в `packages/core/src/`; тесты, эталон SVG, конфигурация Compose, `dist/`, манифест и документация, включая `docs/ROUTING_CPU_GPU.md`.

**Проверки:** `npm run check` (31 тест и сборка), `npm run test:browser` (12 сценариев), `npm run benchmark`, `docker compose config` без запуска, проверка контрольных сумм и игнорирования. Итоговые проверки прошли.

**Осталось:** замерить задержки и память на целевом сервере под реальной нагрузкой. Для 10 CPU рекомендовано начать с 6–8 воркеров с запасом памяти и сравнить p95; перенос на GPU пока не требуется и не реализован. Препятствия в произвольных плотных чертежах по-прежнему могут потребовать ручных правок.

**Уверенность:** высокая по проверенным функциональным сценариям, средняя по оценке производительности на целевом сервере. Деплоя не было.

## Обновление: параллельные листы одного запроса

Один многостраничный проект использует до трёх потоков общего пула, если они свободны; один лист трассируется последовательно. Одно- и многопоточный результат совпадают. На 12 синтетических листах локальная медиана составила 442 мс на одном потоке и 207 мс на трёх.

Изменены серверный пул, воркер и обработчик запроса, разделение трассировки в core, тесты и документация. `dist/` исключён из Git, локальные файлы сохранились; отчёты новых запусков пишутся в `artifacts/`. Старые отчёты не тронуты.

Прошли `npm run check` (33 теста), `npm run test:browser` (12 сценариев), проверка собранного API, `git check-ignore`, `git diff --check` и проверка 327 контрольных сумм. На GitHub исходники не отправлены. Уверенность высокая по проверенным сценариям, средняя по задержкам на целевом сервере.

## Обновление: до восьми потоков

Предел на проект поднят до 8 потоков общего пула. Пустые листы больше не ухудшают распределение заполненных; компоновщик не дублирует ID импортированного листа при автоматическом добавлении следующего. Однолистовой проект остаётся однопоточным. Для выделения восьми потоков через Docker требуется задать `CPU_LIMIT=8` и `SCHEMATIC_BUILD_WORKERS=8`; рабочий `.env` оставлен без изменений.

**Файлы:** `apps/server/src/schematic-build.ts`, `packages/core/src/layout.ts`, `tests/{core,server}.test.ts`, `.env.example`, `docs/ROUTING_CPU_GPU.md` и манифест; локальная игнорируемая сборка обновлена.

**Проверки:** 36 тестов и сборка через `npm run check`, 12 браузерных сценариев, проверка конфигурации Compose, различий и контрольных сумм. Независимый субагент подтвердил эквивалентность результата и успешный расчёт двух одновременных проектов. Целевого сервера не касались.

**Осталось:** реализовать отдельным этапом проверку пересечения закреплённых проводов, короткие ID автотрасс и выборочный пересчёт. Уверенность в проверенных сценариях высокая, серверная производительность и память под реальной нагрузкой не измерены.

## Обновление: редактор проводов, трассировка и расстановка

Провода можно перетаскивать за участок или угол, вставлять и удалять точки двойным кликом. Выводы остаются на месте, разрывающие ответвления движения не применяются. Если для ортогональности поворот всё равно необходим, при удалении выбирается альтернативный угол.

Координаты компонентов необязательны. Авторасстановка оценивает связи с уже размещёнными компонентами; алгоритм делает ограниченный повтор при заторе. Ручные маршруты, пересекающие чужой компонент, помечаются. Введены короткие ID, лимит листов и безопасный повторный расчёт с переиспользованием неизменившихся трасс из RAM.

**Файлы:** редактор, CSS и геометрия жестов в `apps/web/src/`; компоновка, маршруты и лимиты в `packages/core/src/`; worker и новый RAM-кэш в `apps/server/src/`; тесты, README, `docs/ROUTING_CPU_GPU.md` и манифест. Новый формат JSON не требуется.

**Проверки:** `npm run check` (41 тест и сборка), `npm run test:browser` (13 сценариев), `npm run benchmark`, `git diff --check` и манифест. Проверка на удалённом сервере не выполнялась. Уверенность высокая по проверенным сценариям; ускорение на реальной нагрузке не измерялось.

## Обновление: компактная расстановка и вертикальные резисторы

Компоновщик сравнивает горизонтальную, вертикальную и компактную раскладки. Длинная цепочка резисторов может складываться рядами; резистор у земли или питания может встать вертикально. Надписи остаются горизонтальными. «Перестроить свободные» применяет новый алгоритм к мягким позициям без снятия фиксации или изменения ручной проводки.

**Файлы:** `packages/core/src/{auto-placement,layout,geometry,render}.ts`, редактор, серверная проверка опций, тесты, README, `docs/ROUTING_CPU_GPU.md` и манифест.

**Проверки:** `npm run check` — 44 теста и сборка, `npm run test:browser` — 14 сценариев, оба сценария `npm run benchmark`, локальное сравнение ширины и проводов, проверка Git и контрольных сумм. Проект не разворачивался.

**Осталось:** оценить реальную пользовательскую схему после обновления сайта. Глобально оптимальная раскладка не гарантируется. Уверенность по проверенным сценариям высокая.

## Обновление по фото 1–6

Номера выводов остаются читаемыми при повороте. Стрелки получают горизонтальный подвод, земли — вертикальный сверху; точки и подписи не накладываются на уже проложенные линии. Автоматические провода держат ось не ближе 1,25 мм к корпусу. Ручные фиксации сохранены, зазор контролируется предупреждением. Свободные компоненты укладываются плотнее, включая вертикальные конденсаторы у питания.

**Файлы:** `packages/core/src/{auto-placement,geometry,layout,render,routing,types}.ts`, тесты трассировки и браузера, A3 SVG-эталон, README и манифест. Фото не изменены.

**Проверки:** `npm run check` (48 тестов и сборка), `npm run test:browser` (14), `npm run benchmark` (два сценария без диагностик), `git diff --check` и манифест. Уверенность высокая по проверенным сценариям; исходную схему со снимков не перестраивали. Деплоя не было.
