# Создание библиотечного компонента — контракт 1.0

Вы создаёте JSON определения компонента для автономного редактора «ГОСТ Схематика».
Результат — отдельный файл UTF-8 JSON. Не генерируйте HTML, JavaScript, SVG-разметку,
сетевые ссылки или пояснения внутри файла. При сомнении запросите у инженера форму
УГО и физические номера контактов. Приложение не извлекает символы из даташитов.

## Источник истины

Точная машинная схема: `/api/schemas/component.json`.
Актуальная библиотека: `COMPONENT_CATALOG.md`.
Веб-интерфейс не предоставляет текстового JSON-редактора: файл импортируется
в конструктор, проверяется, просматривается и сохраняется в SQLite.

## Обязательные поля

- `format_version`: строка `1.0` — версия файлового формата.
- `component_code`: постоянный уникальный код физической модели. Он неизменяем.
  Удалённый код зарезервирован навсегда. Для копии выбирайте новый код.
- `name`, `category`: непустые имя модели и категория.
- `positional_prefix`: префикс позиционного обозначения, например `R`, `C`, `DA`.
- `description`: необязательная справка, обычный текст.
- `physical_pins`: массив объектов **только** `{ "number": "1" }`.
  Номер — строка, допустимы обозначения корпуса вроде `A1`. Все номера уникальны.
- `variants`: массив заранее определённых графических вариантов.

**Назначения, имена и электрические типы выводов не задаются.** Нет полей `name`,
`function`, `input`, `output`, `power` у физического вывода. Приложение не выполняет
электрический ERC и не проектирует обвязку неиспользованных секций.
Текст внутри УГО допустим как геометрический примитив; он не является семантикой
вывода и не влияет на связность.

## Вариант и секции

Вариант имеет `variant_code`, `name`, `sections`. Подкод уникален внутри компонента.
Секция имеет `section_id`, `graphics`, `pins`; ID постоянен внутри варианта.
Один вариант может показывать весь корпус, другой — несколько отдельных секций.
**Каждый физический вывод должен присутствовать в каждом варианте ровно один раз.**
Все секции выбранного варианта обязательно попадут на схему, даже без соединений.
Секции разных листов остаются одной физической микросхемой с одним обозначением.
Нельзя автоматически делить корпус, скрывать секции или создавать новые варианты.

## Координаты и выводы

Единицы — миллиметры. Локальное начало координат задаёт автор символа; X вправо,
Y вниз. Сетка конструктора по умолчанию 2,5 мм, тонкий шаг 1,25 мм.
`pins` секции — объекты `{number,x,y,side,length?}`. `x,y` — **электрическая точка
подключения на внешнем конце вывода**, а не центр корпуса. `side` — `left`, `right`,
`top`, `bottom`; это направление геометрии, не электрический тип. `length` — длина
линии от точки подключения к корпусу. Провод подключается по номеру, независимо
от того, где нарисована секция.

## Разрешённая графика

Каждый примитив имеет уникальный внутри секции `id` и `kind`:

| kind | Геометрия |
| --- | --- |
| `line` | `x,y,x2,y2` |
| `polyline` | `points:[{x,y},...]` |
| `rectangle` | `x,y,width,height` |
| `circle` | `x,y,r` |
| `arc` | `x,y,r,start,end` — углы в градусах |
| `polygon` | `points:[{x,y},...]` |
| `text` | `x,y,text,align?` (`left`, `center`, `right`) |
| `group` | `children`, необязательные `x,y,rotation,mirror` |

Не передавайте произвольный SVG path, HTML или обработчики событий. Неизвестные
поля запрещены. Все числовые значения конечны; отрицательные радиусы и размеры
запрещены. Приложение ограничивает размер файла, количество примитивов и глубину.
Текст экранируется при выводе в SVG, не исполняется как разметка.
Шрифт, толщины линий и нормативное оформление определяются исходным кодом сайта,
а не параметрами, присланными нейросетью.

## Полный минимальный пример

```json
{
  "format_version": "1.0",
  "component_code": "SYNTH_R_01",
  "name": "Синтетический резистор",
  "category": "passive",
  "positional_prefix": "R",
  "physical_pins": [{"number":"1"},{"number":"2"}],
  "variants": [{
    "variant_code":"01",
    "name":"Основной",
    "sections":[{
      "section_id":"BODY",
      "graphics":[{"id":"body","kind":"rectangle","x":0,"y":0,"width":10,"height":5}],
      "pins":[
        {"number":"1","x":-5,"y":2.5,"side":"left","length":5},
        {"number":"2","x":15,"y":2.5,"side":"right","length":5}
      ]
    }]
  }]
}
```

Это синтетический пример формата, а не утверждение нормативной точности УГО.
Номинал `10 кОм` задаётся экземпляру в схеме; для каждого номинала не создают
новый библиотечный компонент.

## Проверки перед выдачей

1. Все коды, подкоды, ID секций и номера физических выводов заданы и уникальны.
2. Каждый вариант полностью покрывает физические выводы без повторов.
3. На каждом выводе есть внешняя точка подключения и корректная геометрия.
4. Нет электрических назначений выводов, скрытых секций, сторонних ссылок и кода.
5. Сохраните корректный JSON; пользователь импортирует файл, проверит предпросмотр.

При обновлении используется только текущее определение. Истории версий нет.
Несовместимые старые схемы должны получить явную ошибку, а не новые соединения.
